MsQuic execution configuration for T3 (client)
================================================================

Native configuration mechanism in this patched repository:
    There is no separate stock MsQuic .ini file for worker placement.
    The patched quicinterop/quicinteropserver reads these keys from the
    role-local dpdk.ini before RegistrationOpen:

        GreenQuicQuicWorkerCpus=20,21,22,23
        GreenQuicQuicProfile=max_throughput
        GreenQuicProfile=client_download

    It builds QUIC_EXECUTION_CONFIG and calls:
        MsQuic->SetParam(nullptr,
                         QUIC_PARAM_GLOBAL_EXECUTION_CONFIG,
                         ...)

Registration configuration used by the tools:
    QUIC_EXECUTION_PROFILE_TYPE_MAX_THROUGHPUT
    (change MSQUIC_EXECUTION_PROFILE in config.env only for a deliberate comparison)

Configured MsQuic worker CPUs:
    20,21,22,23
Configured worker count:
    4
Configured partition count:
    4

Connection ownership:
    Every connection is owned by exactly one partition/worker at a time.
    Stream count does not create extra partitions: all streams of one
    connection remain under that connection's owner partition.

Final V18 configuration split
-----------------------------
dpdk.ini controls topology, roles, lcores, workers, and partition mapping.
powermng.ini controls four physical EWMAs, QUIC floors, hard-max, DVFS,
idle confirmation, sleep, and logging. Both files are read at process startup.

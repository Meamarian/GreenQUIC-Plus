V21 test-suite update report
============================

Base retained
-------------
* All 22 previous V18.1 cases remain unchanged in purpose and workload.
* Existing launchers, two-host workflow, RAPL checks, manifests, payloads,
  topology files, and in-process-client requirements remain present.

Added
-----
* 11 V21 selectable-idle diagnostic cases, yielding 33 total cases and 66
  statically validated endpoint configurations.
* Complete V19/V21 power keys in every generated powermng.ini.
* Strict V21 configuration validation for idle modes, fallbacks, bounded waits,
  watchdogs, epoll limits, booleans, and topology compatibility warnings.
* V21 stats parser and log validator.
* Mode-specific evidence validation for actions, cumulative counters, lcore
  ownership, hint masks, and forbidden hint/action overlaps.
* Runtime manifest records idle mode, fallback, logging level, and stats period.
* V21 binary marker verification before an authoritative run.
* Per-case run_idle_matrix.sh for exploratory mechanism comparisons.

Methodological safeguards
-------------------------
* Hardware-gated modes use fallback=fail in their dedicated proof case so an
  unsupported API cannot be mistaken for successful mode coverage.
* Monitor is tested on RX-only lcores; role-mismatch fallback has a separate case.
* TX work wakeup is verified using eventfd wake signals and an in-process client.
* ACK and recovery guard cases correlate hint bits with selected actions.
* Diagnostic thresholds/logging are not final energy settings. Repeat chosen
  configurations with logging off and production thresholds for final results.
